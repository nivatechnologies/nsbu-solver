# Standalone W3 layout-768 controls

This harness owns standalone backend controls. `preflight` has no numerical-grid allocation. It derives and checks whole sequential peaks before construction: force serial/W3 phases are 32,343,080,936 / 50,116,792,040 bytes under a 64-GiB external cap; RHS serial/W3 phases are 47,364,321,568 / 72,385,790,112 bytes under a 96-GiB cap. Each W3 phase retains the serial expected coefficients, its actual output, catalog, and a 64-KiB fixed control allowance. The RHS phase also retains its input state. These are exact harness ownership sums, not host-wide launch admission.

`force` and `rhs` require distinct environment gates. Both completed successfully on the frozen source and binary; see the [execution receipt](prepared/runs/completion.json). `force` compares retained-N512/M768 serial and forward-W3 force owners. `rhs` compares retained-N512/padded-768 serial and bidirectional-W3 RHS owners using a strict-Hermitian, divergence-free mixed-direction/mixed-phase fixture whose tiny N4 oracle has nonzero projected advection. Both controls preflight before catalog allocation; exercise a one-byte-under constructor refusal; require exact W3 identity; compare complete coefficient words and work/consumption; and reuse preallocated output buffers inside the three-evaluation allocation region.

Execution receipts include the case SHA-256 and reviewed-admission commit. The control has no observer, trajectory, archive, resume, or qualification path.

Both full-size controls matched serial coefficients bit-for-bit and reported zero steady allocations across three evaluations. The force control took 338.37 seconds and RHS took 356.50 seconds. Root independently verified the terminal log hashes and seven focused W3 core tests, including refusals for 1024 and 1152. These checks admit the 768 backend layout; they do not qualify a trajectory. The original preparation receipt remains historical and does not replace the terminal execution receipt.
