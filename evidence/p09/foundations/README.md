## Implemented behavior

The allocation-free registry borrows caller-reserved records and bounds append
attempts and invalidation visits. Mathematical problem identity is separate from
execution and force-artifact identities. Ordinary continuations preserve exact
clock profile and execution identity. Transfers explicitly retain an inherited-error
report identity; they and their descendants cannot become direct fine branches.
Reference-seeded branches remain local tests. Modified mathematical identity,
foreign/missing parents, invalidated ancestry and inconsistent times are refused.
Invalid declarations spend an attempt without publishing a record.

When revised force evidence exceeds an earlier budget, the caller can invalidate
that artifact. One bounded forward pass invalidates all affected descendants,
including descendants using newer artifacts or transfer records. Unaffected
independent branches remain valid, and repeated invalidation never revives history.
The registry's valid/direct flags describe declared ancestry only. Actual state
provenance, external content hashes and inherited-error report contents still need
verification; this registry never imports or emits numerical acceptance.

`PhysicalImage` captures a live owned Fourier state under an additional memory
reservation. It preserves coefficient bits, exact clock, plan, epoch and accepted
step count in disjoint buffers. Moving its payload back to a state allocates
nothing and performs no projection or rounding. The API accepts no analytical
reference field. It is an in-memory physical payload component, not a serialized
checkpoint. Complete controller, diagnostic/error/reconstruction and lineage
history must accompany a qualified continuation.
