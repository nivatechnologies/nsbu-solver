# Exact-v2 cached trajectory profile

The cached integration profile is an explicit opt-in for exact-v2 trajectories. It changes only
how the integration RHS obtains the original prescribed-force coefficients: the five exact clocks
of one full/two-half attempt are evaluated once and reused within that attempt. State arithmetic,
integrator kernels, accepted histories, force sample layouts, observers, pressure, residuals and
other diagnostic providers are unchanged.

`v2_run::Plan::from_rest` and `v2_experiment::FamilyPlan::new` retain the direct profile.
`Plan::from_rest_cached`, `FamilyPlan::new_cached` and `StartupProfile::plan_cached` opt into the
cache. The same `Run`, `ReconstructedRun`, `V2Family`, `ProbeFamily` and `DiagnosticDriver`
implementations own both profiles. Reconstruction plans inherit their ordinary branch's admitted
integration policy, so the ordinary and independent probe trajectories cannot silently mix direct
and cached integration under one family identity.

The current supported 64-bit target pins the direct owner layouts and refuses admission if they
drift. Adding the opaque boxed cache variant leaves the direct `RunForce`, `Plan`, `Run`,
`ReconstructedPlan` and `ReconstructedRun` sizes unchanged. A checkpoint generated by the
pre-cache binary remains a valid direct version-1 checkpoint, and the historical direct family
identity bytes are unchanged.

Cached families use a distinct identity encoding: `NSBUV2FAMILYC001`, followed by the explicit
`ATTEMPTCACHE0001` profile tag and then the same case/settings/time fields used by the direct
encoding. Probe and downstream diagnostic identities inherit that distinct family digest.

The cached provider's reservation includes the original provider, five three-component retained
coefficient slots, the opaque one-owner box and allocator allowances. The enclosing
`SpectralRhs` reservation separately includes the unchanged inline `RunForce` storage.
`Run::cache_work` and
`ReconstructedRun::cache_work` expose current-attempt provider, lookup and copy work. Existing
`AttemptWork` remains the strict aggregate RHS/observer ledger and is unchanged for direct runs.

Version-1 archive sizing, writing, reading and read-reservation APIs reject cached plans before
processing an output or input buffer. The CLI remains direct. There is no cached checkpoint or
cross-attempt cache in this increment, and no runtime speedup or PDE qualification follows from the
provider-evaluation reduction alone.
